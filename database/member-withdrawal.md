# 회원 탈퇴 예약

## API

모든 요청은 `Authorization: Bearer <accessToken>`으로 인증합니다.

| 메서드·경로 | 요청 | 성공 응답 |
| --- | --- | --- |
| POST `/api/v1/auth/withdrawal` | `{"password":"현재 비밀번호"}` | 200, 예약 상태 |
| GET `/api/v1/auth/withdrawal` | 없음 | 200, 예약 상태 |
| DELETE `/api/v1/auth/withdrawal` | 없음 | 204 |

예약 상태는 `{"requestedAt":"2026-11-16T06:00:00Z","scheduledAt":"2026-11-17T15:00:00Z"}`입니다.
예약이 없으면 두 필드는 모두 null이며, 예약 응답은 `Cache-Control: no-store`입니다.
비밀번호 누락·공백·불일치는 400, 미인증·삭제된 회원의 토큰은 401입니다.
비밀번호 불일치는 기존 오류 응답 형식에 따라 `{"message":"현재 비밀번호가 일치하지 않습니다.","errors":[]}`를 반환합니다.
내부 오류 코드는 `WITHDRAWAL_PASSWORD_MISMATCH`입니다.

같은 예약을 다시 신청해도 시각은 연장되지 않으며 비밀번호는 매번 확인합니다.
예약이 없는 상태에서 취소해도 204입니다. 취소 후 재신청하면 새 신청 시각을 사용합니다.
예약 중 로그인·재발급·조회·프로필 변경은 유지되며, 로그인만으로 취소되지 않습니다.
댓글·답글 작성·수정·삭제, 리뷰 작성·수정·삭제, 도움됐어요 등록·취소는 403으로 차단됩니다.
제한 오류 코드는 `WITHDRAWAL_CONTENT_WRITE_NOT_ALLOWED`이며, 예약 취소 후 다시 이용할 수 있습니다.

## 시간과 취소

한국 시간으로 신청 시각에 24시간을 더한 날짜의 다음 날 00시가 삭제 예정 시각입니다.
11월 16일 15시 신청은 18일 00시, 16일 00시 신청도 18일 00시입니다.
DB와 응답은 Instant(UTC)를 사용하고 날짜 계산은 Asia/Seoul을 사용합니다.

서버는 매일 00시를 포함하여 5분마다, 그리고 시작 직후 기한이 지난 대상을 처리합니다.
서버 중단 중에는 지연될 수 있으며 재시작 또는 다음 실행에서 재시도합니다.
예정 시각이 지나도 실제 삭제 전에는 취소할 수 있습니다. 취소와 삭제는 같은 회원 행을 잠그며,
잠금을 확보하고 커밋한 쪽이 먼저 적용됩니다. 삭제가 롤백되면 취소가 이어서 진행될 수 있습니다.

## 삭제 범위와 이미지

회원 한 명마다 독립된 트랜잭션으로 다음 데이터를 정리합니다.

- 작성한 리뷰와 해당 리뷰의 댓글·답글·좋아요·리뷰 이미지 행·조회수
- 다른 리뷰에 남긴 댓글은 작성자 null, 내용 `삭제된 댓글입니다`, deleted=true로 익명화
- 회원의 좋아요·리프레시 토큰·이미지 업로드 기록·회원 행
- 대표·추가·본문·프로필·미사용 업로드 이미지 키는 중복을 제거해 `reviews_images_delete`에 기록

삭제된 리뷰의 다른 회원 댓글도 함께 삭제됩니다. 남은 리뷰의 다른 회원 댓글과 답글은 보존됩니다.
DB 처리와 이미지 삭제 작업 등록은 함께 커밋되며, 실패 시 해당 회원의 처리 전체를 롤백합니다.
탈퇴 작업에는 회원 정보를 보관하는 별도 이력 테이블이 없습니다. 이메일·닉네임은 삭제 후 다시 가입할 수 있습니다.

R2 파일 삭제는 기존 이미지 정리를 사용하므로 **DB 탈퇴 다음 한국 자정 이후** 실행됩니다.
실패한 파일은 다음 자정에 재시도하며, 리뷰 본문·이미지·회원 프로필이 참조하는 파일은 삭제를 보류합니다.
따라서 DB 삭제가 파일 삭제 완료를 뜻하지 않으며, 기존 공개 파일 URL은 파일 정리 전까지 접근 가능할 수 있습니다.
이미 발급된 업로드 URL은 5분간 유효하지만 다음 자정 파일 정리는 이 기한 이후에 실행됩니다.

## 배포와 확인

1. 배포 전에 `database/member-withdrawal.sql`을 PostgreSQL에 적용합니다. 기존 회원 데이터는 유지합니다.
2. 애플리케이션을 배포합니다. 현재 Flyway는 활성화하지 않으며 기존 V1 파일도 수정하지 않습니다.
3. 회원 탈퇴 처리 로그의 성공·실패 건수와 밀린 예약을 확인합니다.
   지연 조회 예: `SELECT count(*), min(withdrawal_scheduled_at) FROM members WHERE withdrawal_scheduled_at <= now();`
4. 이미지 정리 로그에서 실패·참조 보류 여부를 별도로 확인합니다.

`member.withdrawal-cleanup.enabled=false`는 자동 탈퇴 작업을 비활성화합니다. 기본값은 true입니다.
이미지 정리는 기존 `storage.image-cleanup.enabled` 설정을 따릅니다.
자동 작업을 끄더라도 예약·조회·취소 API는 유지되며 기존 예약은 DB에 남습니다.

`MemberWithdrawalTests`는 기본적으로 H2를 사용합니다.
`WITHDRAWAL_TEST_URL`, `WITHDRAWAL_TEST_USER`, `WITHDRAWAL_TEST_PASSWORD`를 지정하면 같은 테스트를 PostgreSQL에서 실행합니다.
**테스트는 스키마를 생성·삭제하므로 반드시 폐기 가능한 전용 DB를 사용해야 합니다.**
스토리지 호출은 모의 객체이며 실제 R2 동작 검증과는 구분합니다.
